# Question and Finding Routing

Ordinary question:
→ member's own ChatGPT Project first
→ if canonical context resolves it, no GitHub Issue needed

Unresolved contradiction:
→ GitHub Validation Finding
→ mark Context/manuscript conflict
→ Lead decides

Reproducible suspected defect:
→ GitHub Validation Finding
→ one distinct problem per Issue

Cross-scope observation:
→ observer may file Finding
→ include handoff note
→ Lead decides root-cause owner

Architecture/schema/production question:
→ Lead Developer

Manuscript mismatch:
→ Mica audits and reports
→ Lead decides whether manuscript, implementation, both, or client clarification must change

Rule:
QUESTION → ChatGPT first
TEAM-VISIBLE PROBLEM → GitHub Issue
IMPLEMENTATION → Lead-confirmed Issue only
FINAL DECISION → Lead Developer
